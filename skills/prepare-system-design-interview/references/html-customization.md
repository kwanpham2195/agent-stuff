# Reuse the HTML skeletons

For HTML requests, copy and customize [candidate-brief.html](../assets/candidate-brief.html) and, only when requested, [interviewer-guide.html](../assets/interviewer-guide.html). Each is standalone, offline and runnable. Explicit text or Markdown requests stay in that format.

These skeletons use anonymous illustrative content. They preserve the paper/ink/orange palette, system/light/dark themes, 46 px toolbar controls, sticky navigation, collapsible detail and focused jumps. They are not a ready-made exercise.

## Editable content

Replace titles, role, problem, requirements, workload, target boundaries, exclusions, clarification replies, phase questions, reference reasoning and evidence prompts. Choose phase timing for the agreed duration; neither three phases nor any scale, stack or rating is universal. Keep the candidate and private facts consistent without embedding private probes or notes in the candidate file.

The private sample architecture has three labeled actors and a request/record/reply trace. Inputs genuinely update the diagram, highlighted component, trace text and notes export. For a different topology, edit the nodes, arrows and trace descriptions together; do not relabel an incompatible flow. Native controls support keyboard activation. There is no framework, network renderer or arbitrary diagram-language parser.

## Shared structure

Keep theme tokens, toolbar alignment, responsive layout, focus rings, navigation focus/scroll behavior, notes ownership and export warnings. If phases change, synchronize article IDs, `phaseIds`, phase buttons and phase selector options. Update jump options and links whenever anchors change. Preserve deliberate local diagram scrolling instead of shrinking labels to unreadable sizes.

Notes and diagram label edits remain in the open page only. Export includes both note fields and labels, not the whole guide. Export requests a download; check the file before closing. It does not make later edits durable. Print styles show all phases, expanded details and current notes; browser print/PDF behavior still requires verification after customization.

## Before delivery

Remove the sample disclaimer only after the exercise is complete and approved. Inspect candidate source, not just its visible page, for private data, hidden content and private links. Check both files offline for broken anchors, dead controls and external dependencies. Follow [interactive-guide-checks.md](interactive-guide-checks.md) on the customized outputs, including real controls, themes, narrow layout, export and actual paginated PDF when available. Template verification is not evidence for a later customized guide.
