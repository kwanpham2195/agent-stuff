# Bounded skill evaluation

Use these six cases when changing interview instructions. For a static walkthrough, trace the expected decision to the instruction that owns it. Record pass/fail and gaps. Do not call that a generated-interview behavior test. A real behavior evaluation must run the skill on the case in an authorized isolated output location and inspect the produced material.

| Case input | Observable expected result |
| --- | --- |
| “Prepare a senior backend interview” with no duration | Ask for duration or a clearly provisional approval question; no invented final schedule. |
| “Prepare a 20 minute system design interview; candidate and private guide” | Reduce scope/probes, keep a coherent first design and selected failure trace, and reserve candidate questions; timings sum to 20. |
| “Candidate brief only, Markdown” | Only candidate Markdown; no HTML, private answer, notes or hidden private links. |
| Same-role round, optional CV claiming broker expertise | Preserve round competencies/constraints/anchors; treat the claim as optional probe context, not demonstrated ability or a required stack. |
| Candidate proposes a simpler architecture than the reference | Assess stated guarantees, relevant entities/invariants, traces and limits; do not reject for stack mismatch. Distinguish quality/correctness, assistance and coverage. |
| “Guarantee no accepted data loss; acceptance occurs before any durable record; process may crash immediately” | Surface the contradictory contract and seek a decision before finalizing; do not silently weaken either guarantee. |

For an HTML maintenance pass, also exercise both assets with native clicks and keyboard: phases and jumps focus/scroll, themes, detail panels, diagram labels, trace forward/back/reset, notes retention and export. Inspect desktop and narrow layouts in both themes, source privacy and local anchors. Record print CSS inspection separately from an actual PDF/print run.
